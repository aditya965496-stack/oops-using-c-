Introduction to OOP
What is OOP and why use it
▾
EasyExam Favourite

What is OOP?

Object-Oriented Programming (OOP) is a programming model that organizes software design around data (objects) rather than functions and logic. It partitions data into two memory areas: data and functions.

Advantages of OOP

  • Faster and easier to execute
  • Clear structure for programs
  • DRY — Don't Repeat Yourself
  • Reusable code, shorter development time
  • Easier to maintain and debug

OOP vs Procedural

  • OOP: data is central
  • Procedural: functions are central
  • OOP supports real-world modelling
  • OOP = modular, scalable

4 Pillars of OOP

  • Encapsulation — binding data + functions into a class
  • Abstraction — showing only what's necessary, hiding complexity
  • Inheritance — child class gets properties of parent class
  • Polymorphism — same interface, different behavior
Exam tip: Always remember the 4 pillars with the acronym AEIP. Be ready to define each one and give a real-world example.
L01
Classes & Objects
Blueprint vs Instance
▾
Very Important

Class

A class is a blueprint or template used to create objects. It defines what data (attributes) and actions (functions) an object will have.

Example: Car is a class. All cars share wheels, speed, mileage.

Object

An object is an instance of a class. When a class is defined, no memory is allocated. Memory is allocated only when an object is created.

Example: myCar is an object of class Car.

Object Properties

3 Properties of an Object

  • State — represented by attributes (e.g., color, speed)
  • Behavior — represented by methods (e.g., drive(), stop())
  • Identity — unique name to interact with other objects
Syntax
class Student {
public:
    string name;
    int rollNo;

    void display() {
        cout << name << " " << rollNo;
    }
};

int main() {
    Student s1;       // object created
    s1.name = "Aditya";
    s1.rollNo = 228;
    s1.display();      // Output: Aditya 228
}
Key rule: Class = blueprint (no memory). Object = instance (memory allocated). One class → unlimited objects.

What are Access Specifiers?

Access specifiers control who can access the members (data/functions) of a class. They enforce data hiding and encapsulation.

L02
Methods & Message Passing
Functions inside classes, object communication
▾

Methods

Methods are functions that belong to a class. They define the behavior of objects. Can be defined inside or outside the class.

Message Passing

Objects communicate with each other by calling each other's methods. This is called message passing. When you write obj.method(), you're sending a message to the object.

class Fan {
public:
    void turnOn()  { cout << "Fan is ON"; }
    void turnOff() { cout << "Fan is OFF"; }
};

int main() {
    Fan f1;
    f1.turnOn();   // Message: f1, please turn on
}
Outside class definition
class MyClass {
public:
    void show();   // declaration
};

void MyClass::show() {   // definition outside
    cout << "Hello!";
}
Real-life: Pressing elevator button = message passing. The elevator (object) responds to your request (message).
L02
Abstraction & Encapsulation
Hiding complexity, binding data
▾
Very Important

Abstraction

Showing only essential features, hiding internal details. Users see what something does, not how.

Example: You drive a car without knowing engine internals.

Implemented via: abstract classes & interfaces

Encapsulation

Wrapping data + functions into a single unit (class). Prevents direct access to data. Access is via methods only.

Implemented via: access specifiers (private)

Key Difference

  • Abstraction → hides complexity (design-level)
  • Encapsulation → binds data (implementation-level)
  • Abstraction: "What can you do?"
  • Encapsulation: "How is your data protected?"
class ATM {
private:
    double balance = 5000;   // encapsulated (hidden)
public:
    void withdraw(double amt) {    // abstracted interface
        if(amt <= balance) balance -= amt;
        else cout << "Insufficient funds";
    }
}; // User sees withdraw(), NOT balance variable
L05
Default Arguments
Pre-set parameter values
▾

What are Default Arguments?

Default arguments are values provided in function declaration that are used when no argument is passed by the caller.

void greet(string name = "Guest") {
    cout << "Hello, " << name;
}
greet();           // Output: Hello, Guest
greet("Aditya");  // Output: Hello, Aditya

Rules

  • Default arguments must be at the right end of parameter list
  • Once default is given, all following params must have defaults too
  • Cannot have default in both declaration and definition
void f(int a = 10) { cout << a; }
f();    // 10
f(221); // 221
L06
Function Overloading
Same name, different parameters
▾
Important

Definition

Function overloading allows multiple functions with the same name but different parameters (number, type, or order). The compiler picks the right one based on arguments — this is compile-time polymorphism.

class Calculator {
public:
    int    add(int a, int b)              { return a + b; }
    double add(double a, double b)        { return a + b; }
    int    add(int a, int b, int c)       { return a+b+c; }
};

Calculator calc;
calc.add(5, 3);          // → int version
calc.add(2.5, 3.5);     // → double version
calc.add(1, 2, 3);      // → 3-param version
⚠️ You cannot overload by return type alone. The parameter list must differ.
Exam: Overloading = compile-time polymorphism = early binding. Overriding = runtime polymorphism = late binding.
L06
Friend Functions
Non-member with private access
▾
Exam Favourite

What is a Friend Function?

A friend function is not a member of the class but is declared inside the class with the friend keyword. It can access private and protected members of the class.

Why Use Friend Functions?

  • Access private data without being a class member
  • Useful when two classes need to share data
  • Used in operator overloading (e.g., stream operators)
class Box {
private:
    int length = 10;
public:
    friend void showLength(Box b);  // friend declaration
};

void showLength(Box b) {          // NOT a member, but can access private
    cout << "Length: " << b.length;
}

int main() {
    Box b1;
    showLength(b1);  // Output: Length: 10
}
⚠️ Friend functions break encapsulation slightly. Use only when necessary.

Static Members
Class-level data shared by all objects
▾
Important

Static Data Member

  • Belongs to the class, not objects
  • Shared by all objects (one memory copy)
  • Declared with static keyword
  • Defined outside class

Static Function

  • Can only access static members
  • No this pointer
  • Called via ClassName::func()
  • No object required
class Student {
public:
    static int count;       // declaration
    Student() { count++; }
    static int getCount() { return count; }
};
int Student::count = 0;   // definition outside class

Student s1, s2, s3;
cout << Student::getCount();  // Output: 3
Use case: Counting objects created, storing constants shared by all, factory methods.

Object Pointer

A pointer that stores the address of an object. Use -> to access members via pointer.

Student s1;
Student* ptr = &s1;   // pointer to object
ptr->display();       // access via arrow operator

A const object cannot have its data modified. It can only call const member functions.

const Student s2;     // constant object

// const member function — cannot modify data:
void display() const { cout << name; }

Constructors
Default, Parameterized, Dynamic
▾
Very ImportantAlways in Exam

What is a Constructor?

A constructor is a special member function that is automatically called when an object is created. Same name as class, no return type.

Type 1 — Default Constructor
class Student {
public:
    string name;
    int roll;
    Student() {               // default constructor
        name = "Unknown";
        roll = 0;
    }
};
Type 2 — Parameterized Constructor
class Student {
public:
    string name;
    int roll;
    Student(string n, int r) {  // parameterized constructor
        name = n;
        roll = r;
    }
};
Student s1("Aditya", 228);  // pass values at creation
Type 3 — Constructor with Dynamic Allocation
class Array {
public:
    int* data;
    int size;
    Array(int n) {
        size = n;
        data = new int[n];   // dynamic memory
    }
};
TypeParametersUse
DefaultNoneAssign default values
ParameterizedArgumentsInit with custom values
DynamicArgumentsAllocate heap memory
Key rules: Same name as class · No return type · Auto-called on object creation · Can be overloaded
L14
Copy Constructor
Clone an object from another
▾
Important

What is Copy Constructor?

A copy constructor initializes a new object using an existing object of the same class. It creates a copy (like a photocopy of a document).

class Student {
public:
    string name;
    int roll;
    Student(string n, int r) { name=n; roll=r; }
    Student(const Student& s) {   // copy constructor
        name = s.name;
        roll = s.roll;
    }
};

Student s1("Aditya", 228);
Student s2(s1);   // copy constructor called
Student s3 = s1;  // also calls copy constructor

Shallow Copy

Copies pointer values (address). Both objects point to the same memory. Dangerous — deleting one breaks the other.

Deep Copy

Creates a new memory block and copies actual values. Safe for dynamic memory. Must write manually.

Signature: ClassName(const ClassName& obj) — always pass by reference to avoid infinite recursion!
L15
Destructor
Auto-cleanup when object is destroyed
▾
Exam Favourite

What is a Destructor?

A destructor is a special member function auto-called when an object goes out of scope or is deleted. It releases resources (memory, files, sockets). Syntax: ~ClassName()

class FileLogger {
public:
    FileLogger()  { cout << "File opened"; }
    ~FileLogger() { cout << "File closed"; }  // destructor
};

int main() {
    FileLogger f;   // constructor called
}                  // destructor called automatically at end

Rules

  • Same name as class, prefixed with ~
  • No return type, no parameters
  • Cannot be overloaded — only one per class
  • Called in reverse order of construction
Analogy: When you leave a lab, you switch off lights and lock — that's what a destructor does for your object!
L19
Type Conversion
Implicit & explicit casting
▾

Implicit (Auto)

Compiler converts automatically. Happens for compatible types. Widening (small→large) is safe. Narrowing (large→small) may lose data.

Explicit (Type Cast)

Programmer forces the conversion. Use when compiler won't do it automatically, or when precision matters.

// Implicit
int a = 5;
double b = a;     // int → double (safe)
double x = 9.8;
int y = x;        // double → int (9), fractional lost!

// C-style cast (old)
int z = (int)9.8;   // z = 9

// static_cast (modern, preferred)
double avg = static_cast<double>(7) / 2;  // 3.5 not 3

// dynamic_cast (for polymorphism)
Base* ptr = new Derived();
Derived* d = dynamic_cast<Derived*>(ptr);
CastUseSafe?
ImplicitAuto by compilerMostly
(type) C-styleOld methodNot type-safe
static_castNumeric conversionsYes
dynamic_castPolymorphism downcastRuntime check
const_castRemove constUse carefully
reinterpret_castBitwise reinterpretRisky
Common exam Q: Why is 7/2 = 3 and not 3.5? → Integer division. Fix: static_cast<double>(7)/2
L20
Explicit Constructor
Prevent unintended implicit conversion
▾

Problem it Solves

By default, a single-parameter constructor can be used for implicit conversion. This can cause unexpected object creation. The explicit keyword prevents this.

class Distance {
    int meters;
public:
    explicit Distance(int m) { meters = m; }
};

void print(Distance d) { /* ... */ }

print(10);          // ❌ Error if explicit — no implicit conv
print(Distance(10)); // ✅ Explicit is fine
Use explicit whenever you don't want the compiler to automatically create objects from plain values.
L16
Operator Overloading
Redefine operators for user types
▾
Very ImportantAlways in Exam

What is Operator Overloading?

Operator overloading allows existing operators (+, -, <<, >>) to work with user-defined types (objects). It is a form of compile-time polymorphism.

Syntax

return_type operator symbol (parameters)

class Complex {
public:
    int real, imag;
    Complex(int r=0, int i=0) { real=r; imag=i; }

    Complex operator+(Complex c) {  // overloading +
        return Complex(real + c.real, imag + c.imag);
    }
    void display() { cout << real << "+" << imag << "i"; }
};

Complex c1(3,4), c2(1,2);
Complex c3 = c1 + c2;   // calls operator+
c3.display();           // Output: 4+6i

Cannot Overload

  • :: scope resolution
  • . dot operator
  • .* pointer to member
  • ?: ternary operator
  • sizeof
L17
Operator Overloading via Friend Function
Non-member operator
▾

Why Friend for Operators?

  • When the operator needs to access private data of multiple objects
  • When you don't want to use a member function
class Complex {
private:
    int real, imag;
public:
    Complex(int r=0, int i=0) { real=r; imag=i; }
    friend Complex operator+(Complex, Complex);
    void display() { cout << real << "+" << imag << "i"; }
};

Complex operator+(Complex c1, Complex c2) {
    return Complex(c1.real + c2.real, c1.imag + c2.imag);
}

Complex a(2,3), b(1,4);
(a + b).display();   // 3+7i
Difference: Member function operator takes 1 param (other object). Friend function operator takes 2 params (both objects).
L18
Assignment Operator Overloading
Custom deep copy on = assignment
▾

Why Overload = ?

By default, = does a shallow copy. For classes with dynamic memory (pointers), this causes problems. We overload = to do a deep copy.

class MyString {
    char* data;
public:
    // Assignment operator overload
    MyString& operator=(const MyString& src) {
        if(this == &src) return *this;  // self-assign check
        delete[] data;               // free old memory
        data = new char[strlen(src.data)+1];
        strcpy(data, src.data);      // deep copy
        return *this;
    }
};
⚠️ Always check for self-assignment: if(this == &rhs) return *this;
L22
Inheritance Basics
Code reuse through parent-child classes
▾
Very ImportantAlways in Exam

What is Inheritance?

Inheritance allows a derived class (child) to acquire properties and behaviors of a base class (parent). Promotes code reusability and hierarchical classification.

class Animal {             // Base class
public:
    string name;
    void eat() { cout << "Eating"; }
};

class Dog : public Animal {  // Derived class
public:
    void bark() { cout << "Woof!"; }
};

Dog d;
d.eat();   // inherited from Animal
d.bark();  // own method

5 Types of Inheritance

  • Single — one base → one derived
  • Multiple — multiple bases → one derived
  • Multilevel — A→B→C (chain)
  • Hierarchical — one base → multiple derived
  • Hybrid — combination of the above

L27
Composite Objects & Runtime Polymorphism
Has-a relationship and dynamic dispatch
▾

Composite Objects (has-a)

Composition means one class contains objects of another class as data members. Represents a "has-a" relationship.

class Engine {
public:
    void start() { cout << "Engine starts"; }
};

class Car {
    Engine engine;   // Car HAS-A Engine
public:
    void drive() { engine.start(); }
};

Runtime Polymorphism

The correct function is determined at runtime based on actual object type, not pointer type. Enabled by virtual functions.

Composition vs Inheritance: Use "is-a" → Inheritance. Use "has-a" → Composition. Car is NOT an Engine, but Car HAS an Engine.
L28
Virtual Functions
Runtime polymorphism with pointers
▾
Very ImportantAlways in Exam

What is a Virtual Function?

A virtual function is a member function that can be overridden in derived class and is resolved at runtime (late binding). Declared with virtual keyword.

class Base {
public:
    virtual void show() { cout << "Base"; }
};

class Derived : public Base {
public:
    void show() override { cout << "Derived"; }
};

Base* ptr = new Derived();
ptr->show();  // Output: Derived (NOT Base!)
// Without virtual → would print "Base"
FeatureNormal FunctionVirtual Function
BindingCompile-time (early)Runtime (late)
Resolved byPointer typeActual object type
Keyword—virtual
vTable: C++ implements virtual functions using a virtual table (vTable). Each class with virtuals has a vTable containing function pointers.
L29
Pure Virtual Functions & Abstract Classes
Force subclasses to implement
▾
Very Important

Pure Virtual Function

A virtual function with no implementation in base class. Must be overridden in derived class. Declared with = 0.

Abstract Class

A class that contains at least one pure virtual function. Cannot create objects of abstract class. Derived class must implement all pure virtual functions.

class Shape {              // Abstract class
public:
    virtual double area() = 0;  // pure virtual
};

class Circle : public Shape {
    double r;
public:
    Circle(double radius) { r = radius; }
    double area() override { return 3.14 * r * r; }
};

// Shape s;  ❌ Cannot create — abstract!
Circle c(5);
cout << c.area();   // ✅ 78.5
Interface Pattern: A class with only pure virtual functions acts as an interface. All derived classes are forced to implement all methods.

Templates
Generic programming — one code, all types
▾
Important

What are Templates?

Templates allow writing generic code that works with different data types using a single function or class. Like a blueprint — same design, different materials.

Function Template
template <typename T>
T add(T a, T b) {
    return a + b;
}

cout << add(5, 10);       // int: 15
cout << add(2.5, 3.1);   // double: 5.6
cout << add(1, 2);        // int: 3
Class Template
template <typename T>
class Stack {
    T data[100];
    int top = -1;
public:
    void push(T val) { data[++top] = val; }
    T pop()          { return data[top--]; }
};

Stack<int>    intStack;
Stack<string> strStack;

Down Casting & Cross Casting

  • Upcasting — Derived* → Base* (always safe)
  • Downcasting — Base* → Derived* (use dynamic_cast)
  • Cross Casting — between sibling classes in multiple inheritance (use dynamic_cast)

Exception Handling
Handle runtime errors without crashing
▾
ImportantExam Favourite

What is Exception Handling?

A mechanism to handle runtime errors (like divide by zero, file not found) without crashing. Uses try, throw, catch.

KeywordPurpose
tryBlock of code that may cause exception
throwSignals that an exception occurred
catchHandles the exception
int divide(int a, int b) {
    if(b == 0) throw "Divide by zero!";
    return a / b;
}

int main() {
    try {
        cout << divide(10, 0);
    }
    catch(const char* msg) {
        cout << "Error: " << msg;
    }
    // Output: Error: Divide by zero!
}

Multiple catch blocks

try { throw 42; }
catch(int e)   { cout << "int: "   << e; }
catch(string e) { cout << "str: " << e; }
catch(...)     { cout << "Unknown";     }
Error vs Exception: Error = syntax/logic issue. Exception = formal runtime object that "bubbles up" the call stack.
L34

noexcept and unhandled exceptions
▾

Exception Specification

Tells whether a function may throw an exception or not. Acts like a promise to the compiler. In modern C++, use noexcept.

void safeFunction() noexcept {   // promises NOT to throw
    // safe operations only
}

void riskyFunction() {           // may throw
    throw "Error";
}

std::terminate()

Called when an exception cannot be handled — either no matching catch, or exception thrown in noexcept function. It aborts the program immediately.

SituationWhat Happens
Exception not caughtstd::terminate() called
Exception in noexcept fnstd::terminate() called
Exception in destructorstd::terminate() called

Namespaces & std
Avoid naming conflicts
▾

What is a Namespace?

A namespace groups related identifiers (variables, functions, classes) to avoid naming conflicts. The C++ Standard Library is in the std namespace.

namespace MyProject {
    int counter = 0;
    void print() { cout << "MyProject"; }
}

MyProject::print();       // scope resolution operator
using namespace MyProject;
print();                   // now can call directly

std Namespace

  • All standard library functions are in std
  • std::cout, std::cin, std::vector
  • Use using namespace std; to avoid std:: prefix
  • In large programs, prefer std:: prefix explicitly
Best practice: Never use using namespace std; in header files — it pollutes the global namespace for everyone who includes that header.

File Handling & Random Access
fstream, seekg, seekp
▾
Exam Favourite

File Streams

  • ifstream — input (read)
  • ofstream — output (write)
  • fstream — both read and write
#include <fstream>

// Write to file
ofstream outFile("data.txt");
outFile << "Hello File!";
outFile.close();

// Read from file
ifstream inFile("data.txt");
string line;
getline(inFile, line);
cout << line;   // Hello File!
inFile.close();
Random Access
// seekg — move get pointer (reading)
// seekp — move put pointer (writing)
// tellg — get current read position
// tellp — get current write position

fstream f("data.txt");
f.seekg(100);        // jump to byte 100
f.seekg(0, ios::end); // jump to end of file
f.seekg(-10, ios::cur);// go back 10 bytes
cout << f.tellg();    // current position
ModeMeaning
ios::begFrom beginning
ios::curFrom current position
ios::endFrom end
Sequential vs Random: Sequential = read from start every time. Random = jump to specific position directly (much faster for large files).
